# TIME TO GO — 대기시간 맞춤형 스마트 주문 키오스크 (프로젝트 컨텍스트)

> 출처: 알고리즘 최종 정리 PDF(11.23), 5장 실습 매뉴얼, 주제계획발표 PPTX/대본, 실습 보드 사진.
> 기간: 약 2주. 보드: STM32_RTOS_EVAL (PS_STM32_RTOS_V10), μC/OS-II V2.8x, IAR EWARM 8.2+.

## 1. 확정 운영 규칙
| 항목 | 사양 |
|---|---|
| 주문 수량 | 손님 1명당 1잔 |
| 대기열 | 미완료 최대 10건(제조 중 1 + 대기 9), FIFO, 일반/시간제한 간 우선순위 없음 |
| 제조 | 직원 1명, 한 잔씩 순차 |
| 속도 | **가상 1분 = 실제 10초 (6배속)**, 시스템 틱은 그대로 두고 별도 가상시계 (11.24 변경, 기존 5초/12배속 폐기) |
| 알림 | 문자 LCD 제조 중 진행률 바 → 완료 시 `ORDER NNN READY / PICK UP` + LED + 부저 (실제 3초), 알림 중에도 제조·타이머 계속 진행 |
| 메뉴 선택 시간 | 계산하지 않음. 고객 제한시간 카운트다운은 **주문 확정 이후** 시작 |

## 2. 입력/화면 매핑
- 숙련도(전원 ON 시): SW1/SW2 → OFF/OFF=하(1.3), 한쪽 ON=중(1.0), ON/ON=상(0.8)
- S19 일반 주문, S20 시간제한 주문
- GLCD 2×2 분할: 좌상단 카테고리명+픽셀 아이콘, 나머지 3칸 메뉴. S17 이전/S18 다음 페이지
  - 1p COFFEE: S3 아메리카노, S4 카페라떼, S5 바닐라라떼
  - 2p NON-COFFEE: S3 스무디, S4 에이드, S5 티
- 세부 종류 S15/S16: 아메리카노·카페라떼·바닐라라떼 = ICE/HOT, 스무디 딸기/초코, 에이드 레몬/청포도, 티 캐모마일/페퍼민트
  - HOT/ICE 구분 대상: 커피, 라떼. HOT/ICE에 따른 제조시간 차이 없음
  - 티는 **HOT 전용** (ICE 없음, 11.24 확정). 주문 정보의 온도는 HOT으로 고정 저장
- 버튼은 1회 눌림만 유효(디바운스 → 처리 → 해제 확인). 초기화 대상은 입력 이벤트뿐, 주문 데이터는 유지
- S1, S2, S7, S8: 미정(미사용)
- **S6 = 엔터** (11.24 변경, 기존 S14 폐기) — 대기시간 입력 확정, 주문 확정에 공통 사용
- **대기 가능시간 입력 키** (11.24 확정)

| 키 | 동작 |
|---|---|
| S11 | 5분으로 설정 |
| S12 | 10분으로 설정 |
| S13 | 15분으로 설정 |
| S14 | 20분으로 설정 |
| S9 | +1분 |
| S10 | -1분 |
| S6 | 엔터 (입력 확정) |

  - 예) 16분: S13(15분) → S9(+1분) → S6(엔터)
  - S11~S14는 값을 **덮어씀**(누적 아님), S9/S10은 현재 값에 ±1분
  - GLCD에 현재 입력값 실시간 표시
  - 범위: 최소 1분 ~ 최대 30분, 처음 값 0분 (11.24 확정)
    - S9: 30분에서 더 누르면 30분 유지 / 0분에서 누르면 1분
    - S10: 1분에서 더 누르면 1분 유지 / 0분에서 누르면 0분 유지
    - S6: 0분(아직 입력 없음)일 때 누르면 무시하고 입력 화면 유지
- 취소 키, 뒤로 가기 키 없음 (11.24 확정). S7, S8은 미사용

### 주문 화면 흐름 (11.24 확정)
```
[초기 화면] S19 일반 / S20 시간제한
   → (시간제한이면 대기 가능시간 입력: S11~S14 프리셋, S9/S10 ±1분, S6 엔터)
   → [메뉴 화면] S17/S18 페이지, S3~S5 메뉴 선택      예) S3 아메리카노
   → [세부 종류] S15/S16                              예) S15 ICE
   → [주문 확인 화면] 선택 메뉴 + 예상 대기시간 표시   예) AMERICANO ICE / WAIT 3:00
   → S6 엔터: 확정 직전 재검사(알고리즘 11) → 주문번호 발급·FIFO 등록
   → [주문번호 화면] 예) ORDER NO. 003 — 실제 3초 표시
   → [초기 화면]으로 자동 복귀 (다음 손님 주문 가능)
```
- **가능 메뉴 없음 (시간제한 주문):** 입력한 시간(예: 5분) 안에 제조 가능한 메뉴가 하나도 없으면
  GLCD에 "5분 안에 제조 가능한 음료가 없습니다." 표시 → 실제 3초 후 초기 화면으로 자동 복귀 (11.24 확정)
  - 판정 시점: 대기 가능시간 입력 직후, 전체 메뉴(6종)의 예상 수령시간을 계산해 모두 초과인 경우
- **시간 기준 구분 (11.24 확정):** 화면 전환 3초 = 실제 시간 / 메뉴 제조·대기시간 = 가상 시간(가상 1분 = 실제 10초)
- 3초 대기는 실제 시간 기준이며, Display/Order Task에서만 기다림 → 제조·가상시계는 계속 진행
- 주의: 실습 GLCD 드라이버는 5×7 영문 폰트(PE12864_drv_5x7eng) → 한글 문구는 비트맵 직접 출력이 필요.
  안 되면 영문 대체 예) `NO DRINK IN 5 MIN` (GLCD 한 줄 21자)
- 확인 화면의 예상 대기시간은 가상시계 기준으로 계속 갱신 (확정 전까지 앞 주문 제조가 진행되므로)
- 재검사 실패(대기열 10건 초과, 시간제한 초과) 시 경고 표시 후 메뉴 화면으로 돌아감

## 3. 시간 계산
- 제조시간 = 기계 작업 + 수작업 × 숙련도 계수

| 메뉴 | 기계 | 수작업 | 중 기준 |
|---|---|---|---|
| 아메리카노 | 0.5분 | 0.5분 | 1분 |
| 카페라떼 | 0.5분 | 1.5분 | 2분 |
| 바닐라라떼 | 0.5분 | 2분 | 2분 30초 |
| 스무디 | 1분 | 4분 | 5분 |
| 에이드 | 미정 | 미정 | 2분 |
| 티 | 미정 | 미정 | 3분 |

- 예상 수령 = 현재 제조 **잔여**시간 + 앞선 대기 주문 제조시간 합 + 내 음료 제조시간
- 시간제한 판정: 예상 수령 ≤ 입력 최대 대기시간. 초과 메뉴는 숨기지 않고 비활성화, 전부 불가면 재입력 안내
- 확정 버튼 순간 재검사(수용량 + 시간제한) → 통과 시 주문번호 발급, 실패 시 경고
- 위험도: 여유 = 고객 남은 대기 가능시간 − 예상 완료까지 남은 시간
  - NORMAL > 2분, WARNING 0~2분, DANGER < 0 (단계가 바뀔 때만 부저)

- 6배속 환산 (가상 → 실제): 1분 → 10초, 2분 → 20초, 2분 30초 → 25초, 3분 → 30초, 5분 → 50초, 10분 → 100초
  - 예) 알고리즘 15번: 001 아메리카노 10초, 002 카페라떼 30초, 003 스무디 80초 → 실제 10초 후 001 완료, 002 20초·003 70초 남음
  - 구현: SysTick 1ms 기준 실제 10초 = 가상 60초 → 실제 1초마다 가상 6초 증가 (또는 실제 100ms마다 가상 0.6초)

## 4. 제조·상황 변경
- 타이머 0 → READY → 알림 Task에 전달 → GLCD 현황판에서 제거 → 다음 주문 즉시 시작

### 문자 LCD / LED / 부저 동작 (11.24 확정, 영문 표기)
| 상태 | LCD 1행 | LCD 2행 | LED·부저 | 지속 |
|---|---|---|---|---|
| 제조 중 | `002 CAFE LATTE` (주문번호 + 메뉴) | 진행률 바 16칸 | 꺼짐 | 완료될 때까지, 0.1초마다 갱신 |
| 제조 완료 | `ORDER 001 READY` | `PICK UP` | 켜짐 | **실제 3초**, 이후 OFF |
| 주문 없음 | 대기 문구 (미정) | | 꺼짐 | 새 주문까지 |

- 흐름: ORDER 001 READY(3초, 부저·LED) → 002 진행률 바 → ORDER 002 READY(3초) → 003 진행률 바 → … 대기열이 빌 때까지
- **진행률 바 (2행 16칸)**
  - 진행률(%) = 경과 제조시간 / (경과 + 남은 제조시간) × 100 — 가상시간 기준, 제조시간에 비례
  - 채울 칸 수 = 진행률 × 16 / 100 (1칸 = 6.25%), 0.1초(실제)마다 다시 그림
  - 채운 칸: HD44780 ROM 문자 `0xFF`(꽉 찬 블록), 빈 칸: 공백 또는 CGRAM 사용자 문자(테두리 칸)
  - (선택) CGRAM에 1~5줄 채운 문자 5개 등록 → 16칸×5 = 80단계로 부드럽게 채움
  - `DELAY` 입력 시 분모(전체 시간)가 늘어나므로 바가 살짝 줄어드는 것이 정상
- 1행 메뉴명 16자 제한: `NNN ` 4자 + 메뉴 최대 12자 → `VANILLA LATTE`(13자)는 `VANILLA LT` 등으로 축약
  - 메뉴명: AMERICANO, CAFE LATTE, VANILLA LT, SMOOTHIE, ADE, TEA
- 3초 알림 중에도 다음 주문 제조는 이미 진행 중 (알림은 Task_Alert/Display에서만 대기, Task_Kitchen은 멈추지 않음)
  → 3초 뒤 바는 0%가 아니라 이미 진행된 만큼 채워진 상태로 표시됨
- 완료 이벤트는 메시지 큐로 전달 → 알림 도중 또 완료가 오면 쌓였다가 순서대로 3초씩 표시

### 시간 적용 기준 (가상 1분 = 실제 10초)
| 가상(기계) 시간 | 실제(현실) 시간 |
|---|---|
| 메뉴 제조시간, S9~S14 입력값, 고객 대기시간, 예상 수령시간, DELAY 입력값, 위험도 기준(0~2분), 제조 진행률 | 주문 완료 화면 3초, 주문 불가 화면 3초, 초기 화면 복귀 3초 후, LCD 완료 표시 3초, LED 3초, 부저 3초, LCD 진행률 갱신 0.1초, 버튼 디바운싱 0.03초(30ms) |

- 즉시 처리(실제): 버튼 입력·화면 전환, 숙련도 변경 반영, UART 명령 처리, 주문 취소 반영, 다음 음료 제조 시작

- 금지: Task_Kitchen 안에서 긴 지연으로 부저/LCD 대기
- UART 관리자 명령: `DELAY 60`(제조 중 음료 잔여시간에만 가상 60초 추가, 제조 중 없으면 무시),
  숙련도 변경(제조 중 음료 유지, 대기 주문부터 새 계수), 취소 승인(승인 시점에 WAITING일 때만), `STAT`

## 5. 응용 Task 10개
Task_Input, Task_Order, Task_Scheduler, Task_Estimator, Task_Kitchen, Task_Clock,
Task_Display, Task_Alert, Task_UART, Task_Monitor
(+ 라이브러리 내부: KeyScanTask, TmrTask, TaskStart, Idle, Stat)

RTOS 도구: MsgQ(입력/주문/완료 이벤트), Mutex(대기열·상태), Semaphore(동기화·GLCD), Event Flags(지연·완료·교대·화면 갱신), 타이머/지연.

코딩 우선순위: ① 키패드 선택 + GLCD 동적 표시 → ② 숙련도 제조시간 + FIFO → ③ 예상시간·시간제한·확정 재검사 → ④ 6배속 제조 + 비차단 알림

## 6. 보드/실습 API 메모 (5장 매뉴얼)
- MCU STM32F103VET6, SysTick 1ms (`SysTick_Configuration()`), 기본 스택 512B (`OS_TASK_DEF_STK_SIZE`)
- 초기화: `BSP_Init(); DelayMS(300); GLCD_init(); GLCD_clear(); LCD_initialize(); OSInit(); ... OSStart();`
- GLCD(PE12864, 128×64): `GLCD_xy(row 0~7, col 0~20); printf(...)` — 공유 자원이므로 세마포어로 보호
- 문자 LCD 16×2(I2C): `LCD_string(0x80, ...)` 1행, `LCD_string(0xC0, ...)` 2행
- LED: `LED_TOGGLE(0~3)` / 부저: `GPIO_SetBits/ResetBits(GPIOD, GPIO_Pin_15)`
- S19: `GPIOD Pin10` (0 = 눌림), SW1 토글: `GPIOC Pin6`
- 4×4 키(S3~S18): `KeyInit()`(OSInit 다음), `KeyHit()`, `KeyGetKey(to)`(스캔코드, 타임아웃 시 0xFF)
  - key.c는 2초 누르면 자동 반복 → 알고리즘 2와 충돌하므로 반복 끄거나 무시 필요
- UART1 9600bps: `CommInit()`, `CommGetChar(COMM1, to, &err)`, `CommPutChar(COMM1, c, to)`, ISR `USART1_IRQHandler`
- 메시지 큐: `OSQCreate(tbl, N)`, `OSQPost`, `OSQPend`, `OSQAccept`
- 뮤텍스: `OSMutexCreate(PIP 우선순위, &err)` — 비어 있는 우선순위를 PIP로 예약해야 함
- 이벤트 플래그: `OSFlagCreate`, `OSFlagPost(..., OS_FLAG_SET)`, `OSFlagPend(..., OS_FLAG_WAIT_SET_ANY + OS_FLAG_CONSUME, to, &err)`
- 타이머(ESBB TMR.c, 0.1초 단위): `TmrInit/TmrCfgFnct/TmrSetT/TmrSetMST/TmrStart/TmrStop/TmrChk`
  - 실습 예제의 타임아웃 콜백 안 `OSTimeDly` 사용은 TmrTask를 막음 → 이 프로젝트에선 피할 것
- 통계: `OSStatInit()`, `OSCPUUsage`, `OSCtxSwCtr`, `OSTaskCtr`, `OSTaskStkChk()`(CreateExt + STK_CHK 필요)

## 7. 미결/확인 필요 사항
1. 에이드(2분)·티(3분)의 기계/수작업 분리 비율 (숙련도 계수 적용 범위). 세부 종류(딸기/초코, 레몬/청포도, 캐모마일/페퍼민트)별 시간 차이 여부
2. (확정됨) 대기시간 범위 1~30분, 처음 값 0분, 취소/뒤로 가기 없음
3. 알고리즘 21(고객 취소 요청)의 키오스크 입력 방법 — 취소 키가 없으므로 UART 관리자 명령만으로 처리할지 결정 필요
4. 실제 GLCD 비트맵 출력 함수 유무(픽셀 아이콘 구현 방식)
5. key.c 스캔코드 ↔ S3~S18 실제 매핑은 보드에서 확인
